# The daemon: environment, files and logs

`clusiad` is started on demand by `clusia`, `clusia-tray` and `clusia-app` (and at login by
the LaunchAgent). For the default data folder, when the LaunchAgent is loaded, they ask launchd
to start it (`launchctl kickstart`), so launchd restarts it after a crash; otherwise they start
it themselves. It is one process per data folder; a lock file and the socket keep a second
one from starting.

## Which environment the daemon sees

A daemon inherits the environment of whoever started it, and keeps it until it stops:

| Started by | Environment |
|---|---|
| a terminal (`clusia prs`, `clusia daemon start`) | that shell's, including `PATH` and any `CLUSIA_*` variable |
| the app or the tray opened from Finder or the Dock | launchd's: a bare `PATH` (`/usr/bin:/bin:/usr/sbin:/sbin`) |
| the LaunchAgent (login, restart after a crash) | the plist's `EnvironmentVariables`: `PATH=/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin` |

Because the first start wins, a `CLUSIA_*` variable exported in one terminal does nothing for a
daemon that is already running: stop it (`clusia daemon stop`) and start it again from where
the variable is set.

`gh` and the agent tools (`claude`, `codex`) are looked up in order: the folders of `PATH`,
`~/.local/bin`, `~/.claude/local`, `/opt/homebrew/bin`, `/usr/local/bin`. A bare `PATH` therefore
does not hide a Homebrew install. The agent's turns start the program of `harness.program` (default: `claude` on the `PATH`) with the daemon's environment minus `GH_TOKEN`, `GITHUB_TOKEN`, `GH_ENTERPRISE_TOKEN` and every `CLUSIA_*` variable. With `harness.kind = codex` and no `harness.program`, the program is `CLUSIA_CODEX_BIN` when it is set (it replaces the lookup) and `codex` otherwise, looked up in the same folders. With `harness.kind = custom` the program is exactly `harness.program`, and it must be an absolute path: there is no PATH lookup and no environment override, so a bare or relative name is refused ("… is not an absolute path. Set it in Config › Harness"; a relative `PATH` entry plus `cwd` = the worktree would run a file from the pull request) and a missing program is an error ("… was not found. Set it in Config › Harness"), never another tool. `scripts/sp2-m5-check.sh` tests the `codex` found on the `PATH`.

The agent's turns run in `--permission-mode default` and ask `clusiad permission-bridge`, a small stdio server that `claude` itself starts (from `--mcp-config`, with `--strict-mcp-config`, so your own MCP servers are not loaded in those turns). The bridge forwards each request over the daemon's socket and only the daemon decides: no answer, an error or a bridge that cannot reach it means deny. With `harness.sandbox` on (default), the turn also gets `--settings` with the sandbox enabled (no network, writes only in the worktree). `harness.permission_timeout_secs` (default 120, 30 to 600) is how long a request waits.

The security check and the audit are two more turns of the same kind. Each one is a `claude -p` with `--resume <review session> --fork-session --session-id <new id>` (or just `--session-id <new id>` when the review has no session yet), so it inherits what the chat read and the chat's session is never replaced by the fork's. A check has the chat's command line and permissions (the sandbox, the permission bridge, hooks off, no token, `cwd` = the worktree); only the prompt differs, and a custom audit area's instruction only ever reaches the prompt. A turn id comes from the review's own counter, shared by chat turns and checks, and `PermissionAsk` is accepted from the running chat turn or a running check of that review. At most 2 checks run at once (a separate limit from the chat's 3 turns), each for at most `harness.check_timeout_secs` (default 600, 60 to 1800).

The revalidation of a saved review is one more turn of that kind (`origin: revalidation` on its permission requests, so the modal says "Revalidation wants to …"). When polling finds a new head on a saved review, or a window opens a review whose head moved, the daemon relocates the draft's anchors as before, then opens a round in the review file: the anchors it had, the commits, the counts of the deterministic relocation and a timer `harness.revalidate_quiet_secs` long that every further push restarts. Opening the review before the timer fires runs the round at once. When the timer fires the round waits for one of the checks' 2 places and runs for at most `harness.check_timeout_secs`. The prompt carries the old→new diff (3 lines of context, at most 150 000 bytes), the new commits and every accepted draft item that can carry a comment; the agent answers with one `clusia-revalidation` block per item. A block that cannot be read, names an unknown item or moves a comment off the new diff is dropped and counted, and an item with no valid block is stored as *not checked*. The turn stores proposals only: the draft changes on `DecideProposal`, `AcceptAllProposals` or `ReanchorDraftItem`, and a decision whose item changed since the proposal is refused with `conflict`. A new head during the run stops it and restarts the timer; publish, discard, `StopRevalidation` and shutdown stop it and cancel its pending permission requests. A round left `running` by a crash is scheduled again at the next start. The notification of a new head is held for the round: one "Review #N revalidated: …" when it is done, the usual "new commits" one when it failed.

The diagrams of a change are two more kinds of turn, both forked like the checks (`--resume <review session> --fork-session` for Claude Code, `thread/fork` for Codex, a fresh session with the pull request and `review.md` for a custom command) and both with the origin `diagrams` (as `revalidation` and the checks have theirs), so they never reach the chat. When a window or `clusia diagrams --draw` asks, or a review opens with `harness.diagrams` on and no version for its head, one run per review starts: a plan turn that picks up to eight diagrams, then one draw turn per entry, one at a time. Every turn waits in the same queue as the checks (at most 2 run at once across all reviews) and stops at the check timeout. A drawing over 256 KiB is rejected before it is parsed; the answer must hold exactly one fenced `clusia-diagram-plan` or `clusia-diagram` block, which is validated (kind subsets, caps, ids, anchors that must name files of the pull request); when it is invalid, one repair turn runs in a fresh fork whose prompt carries the invalid answer (cut to 20 000 characters) and the errors. The version is written when the plan returns and after every entry changes, so Stop, closing the review, a daemon shutdown or a crash leaves a readable file whose unfinished entries load as *Not drawn*. A version's commit is pinned under `refs/clusia/diagrams/pr-<n>-v<k>` in the repository, so its code can still be read after a force-push; publishing or discarding the review removes the drawings and the pins, closing keeps them.

A click on a box asks the daemon to read its code (`ReadDiagramCode`): from the worktree when the version is at the review's head (the path is canonicalized and must stay inside the worktree, be a regular file and be at most 2 MiB), else with `git show <commit>:<path>`. The comment (`AddDiagramComment`) takes its anchor from the stored drawing, never from the window; the daemon maps the lines from the version's commit to the review's head and adds a line comment when every line is in the pull request's diff, and a general comment with the body `path:start-end: comment` otherwise. Both are `origin: diagram` items in the draft. A version is out of date when its commit is not the review's head; a revalidation round that runs while a version exists also asks the agent for a `clusia-diagrams-stale` block (`{"stale": bool, "reason": "…"}`), and a `stale: false` answer withdraws the offer to redraw.

With `harness.kind = codex` the turns do not start a program per turn. `CodexServer` (`clusiad/src/codex.rs`) keeps one `codex app-server` child per open review, started on the review's first turn with `cwd` = the worktree and the same dropped environment as Claude's plus `CODEX_API_KEY`, `OPENAI_API_KEY` and `MCP_TOOL_TIMEOUT` (`CODEX_HOME` is never set), and speaks JSON-RPC over its stdio. The chat uses `thread/start` (first turn) or `thread/resume`; the checks and the revalidation use `thread/fork`, so the chat's thread is never resumed by them or replaced by their ids. Every thread carries `sandbox: "read-only"`, `approvalPolicy: "on-request"`, the role prompt as `developerInstructions`, `approvalsReviewer: "user"`, hooks off, `mcp_servers = {}`, `notify = []` and `project_doc_max_bytes = 0`. The user's own `.rules` files still apply to the commands Codex runs. Each `item/commandExecution/requestApproval` and `item/fileChange/requestApproval` goes through `permissions::ask` (a command is a `Bash` request, a file change an `Edit` one), the answer is `accept`, `decline` or `cancel` (a Stop), `acceptForSession` is never sent, and any other server request is declined. A stop or the turn deadline sends `turn/interrupt` and kills the process if the turn has not ended 10 s later; the next turn of the review starts a new process. `reviews::close`, publish, discard and daemon shutdown end it (stdin EOF, then a kill after 2 s), and a process with no turn for 30 minutes is ended by a sweep that runs every minute. The probe runs `codex --version` (0.162.0 is the minimum) and `codex login status`.

With `harness.kind = custom` each turn starts one process, as Claude's do, but speaks Clúsia's JSON-lines protocol (`docs/harness-protocol.md`). `clusiad/src/custom.rs` runs `<harness.program> <extra_args>` in the worktree, in its own process group (the program is the absolute path, as above), with the daemon's environment minus `GH_TOKEN`, `GITHUB_TOKEN`, `GH_ENTERPRISE_TOKEN` and every `CLUSIA_*` variable (`MCP_TOOL_TIMEOUT` and the OpenAI keys stay: they belong to the user's own program). It writes one `turn` line to stdin and keeps stdin open for permission replies; stdout is read line by line with caps (1 MiB a line, 10 000 lines and 8 MiB a turn, then the turn ends and the process is terminated). Every `permission` line goes through `permissions::ask` in its own task, as Codex's approvals do: `command` is a `Bash` request, `edit` an `Edit` one (refused without asking unless every path is inside the worktree), `other` an `Other` one with only Allow once and Deny; an unknown kind, a missing or duplicate id is refused, a request made while 8 others wait is refused with one `deny` ("too many requests at once"), and a timeout, a Stop or an error is a `deny`. After `final` or `error` stdin is closed and the process has 10 s to exit, then gets SIGTERM to the group and SIGKILL 10 s later; at shutdown, or when the review is closed, published or discarded, each of these waits is cut to 2 s. Nothing sandboxes the program: it runs as the daemon's user and can talk to the daemon socket, like any program you start. A Stop or the deadline closes stdin, sends SIGTERM to the group and SIGKILL 10 s later. The chat sends `session_id` only when the stored session belongs to the same program; the security check, the audit and the revalidation always send `null` and drop the session they get back. The probe starts the program, writes one `probe` line and waits at most 5 s for its answer; a good one fills `harness.custom_name` when it is empty. `clusia harness test` runs the same program against the protocol from the CLI.

| Variable | Meaning |
|---|---|
| `CLUSIA_HOME` | the data folder (default `~/Library/Application Support/Clusia`) |
| `CLUSIA_GITHUB_API` | GitHub API base URL (GitHub Enterprise, tests) |
| `CLUSIA_GITHUB_TOKEN` | a token that wins over `gh` and the Keychain |
| `CLUSIA_GH_BIN` | the `gh` program, overriding the lookup |
| `CLUSIA_SECRET_STORE=memory` | keep secrets in memory instead of the Keychain (tests) |
| `CLUSIA_TRAY_BIN` | the tray program; `none` disables it |
| `CLUSIA_CLAUDE_BIN` | the `claude` program the review agent runs when Config › Harness names none, and first run looks only there |
| `CLUSIA_CODEX_BIN` | the `codex` program the review agent runs when Config › Harness names none and `harness.kind` is `codex`, and first run looks only there |
| `CLUSIA_DAEMON_BIN` | the daemon program the clients start |
| `CLUSIA_GIPHY_API` | Giphy API base URL |

## Files

| File | What |
|---|---|
| `<data>/clusiad.sock` | the socket, created private (mode 0700: the daemon's umask is 077) |
| `<data>/clusiad.lock` | held (`flock`) by the running daemon; the OS drops it when the daemon dies |
| `~/Library/Logs/Clusia/daemon.log` | the daemon's log |
| `~/Library/Logs/Clusia/tray.log` | the tray's output |
| `~/Library/Logs/Clusia/app.log` | the window's log |
| `~/Library/Logs/Clusia/daemon.start.log` | what each start printed before the log opened; appended to, emptied once past 256 KiB |
| `<data>/agent/<owner>~<repo>~<n>.jsonl` | the agent's chat log of a review (every event; 0600; at most 2 MB, then the oldest half is dropped) |
| `<data>/agent/<owner>~<repo>~<n>.state.json` | the suggestions you accepted or dismissed, the head the last summary saw and the review's permission rules (`Bash(cargo test:*)`, `Edit`), which end with the session |
| `<data>/checks/<owner>~<repo>~<n>.json` | the results of the security check and the audit of a review: the head they checked, the findings with their proposed comments, the passes and the number of blocks that could not be read. Deleted when the review is published or discarded, and swept like the review cache. The finding ids you accepted or dismissed live in the review's `.state.json` |
| `<data>/diagrams/<owner>~<repo>~<n>/v<n>.json` | one version of the diagrams of a review: the commit, who drew it, the plan and each entry's drawing, state and notes. A version is not rewritten once done, except for a retry or a redraw of one entry on the latest. A file that cannot be read is skipped with a log line and never renamed or deleted. Deleted when the review is published or discarded; swept like the checks files by age |
| `refs/clusia/diagrams/pr-<n>-v<k>` (in the repository) | pins the commit of version `k` so its code survives a force-push; removed with the drawings |
| the review file (`<data>/reviews/…`), key `revalidation` | the round of a saved review: the heads, the new commits, the anchors before the relocation moved them, the relocation's counts, the state (`scheduled`, `waiting`, `running`, `done`, `failed`), the proposals with their decision and the fingerprint of the comment they were made for, how many results could not be read, and when it finished. Removed with the review when it is published or discarded |
| `<worktree>/.clusia/review.md` | what the agent reads first: the pull request, the draft, the summary (excluded from git through the worktree's `info/exclude`). Never written through a symlink: when the pull request makes `.clusia` anything but a folder, the notes are not written |
| `~/Library/Logs/Clusia/daemon.launchd.log` | what a daemon launchd started printed (the login agent's output); not rotated |

Each log starts a new file every day: yesterday's becomes `daemon.YYYY-MM-DD.log`, and the
current file plus the six before it are kept. Logs are readable by the owner only. With
`--home` or `CLUSIA_HOME` the logs go to `<data>/logs/` instead of `~/Library/Logs/Clusia/`.
